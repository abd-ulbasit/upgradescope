WARNING: the read API is OPEN (server.allowAnonymousRead or
server.ingress.allowAnonymousRead, and no server.readToken): the clusters,
the dashboard's data and /api/v1/gate need no credential for anyone who can
reach the server, and a read token minted in the database closes it only
while that database lasts. A lost or restored database
{{- if not .Values.server.persistence.enabled }} (server.persistence.enabled=false: every pod restart){{ end }}
opens it again. Requests for a Host other than the Service's names,
server.ingress.host, server.allowedHosts, localhost and the pod's address
get 421. To close it for good, drop the allowAnonymousRead value(s) and mint
a read token (below).
{{- else }}

The read API is closed: reads, the dashboard's data and /api/v1/gate return
401 until you mint a read token (server.readToken is empty and the server
runs with --require-read-credential, so a lost or restored database cannot
reopen it). Mint a fleet-wide one; the token is printed once:
{{- if include "upgradescope.postgres" . }}
  kubectl -n {{ .Release.Namespace }} exec deploy/{{ include "upgradescope.serverFullname" . }} -- /upgradescope tokens create --read --teams '*'
{{- else }}
  kubectl -n {{ .Release.Namespace }} exec deploy/{{ include "upgradescope.serverFullname" . }} -- /upgradescope tokens create --read --teams '*' --db /data/upgradescope.sqlite
{{- end }}
A read token is scoped to teams (--teams payments --teams checkout) or '*'
for the fleet. Minted tokens live in the database: after losing it, mint
again. Or set server.readToken (a Secret key, rotated without a restart).

Rotating a token or a webhook URL needs no restart. serve and the agent read
them from files mounted from the Secrets (no subPath, so the kubelet updates
the files) and re-read a file when it changes, checked at most every 5s when
a request or a push needs it. After you change server.ingestToken, readToken,
adminToken, slackWebhook, webhook, webhookSecret, agent.serverToken, or the
contents of a Secret you named (server.existingSecret, agent.existingSecret),
the new value is in use once the kubelet has synced the mounted Secret
(up to about 60 to 90s at its default settings) plus that 5s; until then the
old value still works. An agent push that arrives in that window with a token
the server has already dropped gets a 401 and is retried at the next tick.
A new file that is empty or unreadable keeps the old value, and the pod logs
an error naming the file.{{ if and .Values.server.enabled (gt (int .Values.server.replicas) 1) }} Each server replica's kubelet syncs the Secret on its own schedule,
so for up to that window a push can get a 401 from one replica and a 200 from
another.{{ end }} A UPGRADESCOPE_*_TOKEN in server.extraEnv or agent.extraEnv no
longer overrides these files: set the value in the Secret. No pod annotation carries a function of a secret
value, so the pods are not restarted by a rotation.

A restart is still needed for a value that does not come from the mounted
files: the database URL (server.database.existingSecret), anything you pass in
server.extraEnv, agent.extraEnv, server.extraArgs or agent.extraArgs (read
once at start), and a Slack or webhook URL that was not set when the server
started (a notification sink exists only if its URL was set at start). Then:
  kubectl -n {{ .Release.Namespace }} rollout restart{{ if .Values.server.enabled }} deploy/{{ include "upgradescope.serverFullname" . }}{{ end }}{{ if .Values.agent.enabled }} deploy/{{ include "upgradescope.derived" (dict "root" . "suffix" "-agent") }}{{ end }}
{{- end }}
