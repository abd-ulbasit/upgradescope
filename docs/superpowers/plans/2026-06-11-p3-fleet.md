# upgradescope P3 — Fleet Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development. TDD throughout; conventional commits + `Co-Authored-By: Claude Fable 5 <noreply@anthropic.com>`.

**Goal (spec §11 P3):** multi-cluster rollups, team attribution + server-side mapping, Postgres backend, CI gate endpoint + GitHub Action, auditor CSV/HTML export, per-cluster ingest tokens, per-team scores.

Leaner plan than P1/P2: contracts + test requirements; implementers write the code TDD-style. The P2 `storetest.RunStoreConformance` suite is the Postgres spec.

## Track 1 — Postgres store (`internal/server/store/postgres.go`)

- Driver: `github.com/jackc/pgx/v5/stdlib` (database/sql). NEW DEP — coordinate: pre-pinned on main before tracks start.
- `OpenPostgres(dsn string) (*Postgres, error)` — runs the same embedded migrations via `Migrate` (already driver-agnostic). Add `migrations/0001_init.sql` compatibility: SQLite-specific SQL (AUTOINCREMENT, BLOB) must be split: keep `migrations/` as-is for SQLite; add `pgmigrations/0001_init.sql` (BIGSERIAL, BYTEA, TIMESTAMPTZ — times as timestamptz, not TEXT; store layer converts). Document divergence in both files' headers.
- Conformance: `RunStoreConformance` against Postgres, env-gated `UPGRADESCOPE_PG_TEST_DSN` (skip when unset). Provide `hack/pg-test.sh`: `docker run --rm -d postgres:17-alpine`, export DSN, run tests, teardown. Makefile target `pg-test`.
- `serve --db` stays SQLite; new flag `--db-url postgres://...` (mutually exclusive). Wire in serve.go.
- Per-cluster tokens (spec §8): `tokens` table (both backends; new migration 0002): id, cluster_name, token_hash (sha256), created_at, revoked_at NULL. Store methods: `CreateToken(ctx, clusterName, token) error` (hash inside), `ValidToken(ctx, token) (clusterName string, ok bool, err error)`, `RevokeToken(ctx, clusterName)`. Conformance subtests. Ingest auth: per-cluster token valid only for its clusterName (403 on mismatch); shared `--ingest-token` still accepted (back-compat, docs say "single-cluster/dev"). CLI: `upgradescope tokens create|revoke <cluster> --db|--db-url` printing the generated token once.

## Track 2 — Server fleet features (`internal/server/`, `internal/cli/`, `action/`)

1. **Team mapping override** (spec: labels + server override). Server config `--team-map file.yaml`: list of `{pattern: "payments-*", team: "payments"}` (glob via path.Match, first match wins, applied over namespace→team from inventory labels at evaluation time). Engine already attributes via `inventory.Namespaces[].Team`; server override rewrites that slice before `Evaluate`. Tests: label-only, override-wins, no-match keeps label.
2. **Per-team scores**: `engine.TeamScores(r Report) map[string]TeamScore` (TeamScore{Score int, Ready bool, Blockers, Warnings int}) — same formula over each team's findings subset (finding with N teams counts for each; teamless findings → team "" rendered as "unattributed"). Golden-adjacent table tests. Exposed: `GET /api/v1/clusters/{id}/teams?target=` and in report JSON (`Report.Teams` computed server/CLI-side, NOT stored in engine Report — keep engine pure; add `teams` to the CLI table output as a section when ≥1 named team).
3. **Fleet rollup**: `GET /api/v1/fleet?targets=1.37,1.38` → matrix: rows = clusters, cols = requested targets (default: each cluster's stored targets), cells = {score, ready, blockers} from latest evaluations (no recompute; missing → null). Plus `GET /api/v1/fleet/teams?target=` → team → aggregated {worstScore, clusters[], blockers}. Tests with fake store.
4. **CI gate endpoint**: `POST /api/v1/gate?target=1.38&cluster=<id|name>` body = manifest bundle (tar.gz or concatenated YAML; accept `Content-Type: application/x-yaml` single stream first — keep simple). Server: parse manifests (reuse `collect.CollectFiles` logic — refactor its core into `collect.CollectManifests(r io.Reader)` or write docs to temp dir; pick cleanest), MERGE with cluster's latest inventory context if `cluster` given (manifest GVKs evaluated against target + cluster's add-ons/skew context), evaluate, return Report JSON; `?format=sarif` for SARIF. Auth: read token. Tests: manifest with removed API → blocker; no cluster context → manifests-only.
5. **GitHub Action** (`action/`): composite action.yml — installs released binary (or `go install` fallback), runs `upgradescope scan --files $INPUT_PATH --target $INPUT_TARGET --output sarif --fail-on $INPUT_FAIL_ON > results.sarif`, uploads via `github/codeql-action/upload-sarif` example in README snippet. Inputs: path, target, fail-on. No marketplace publish (P4).
6. **Auditor export**: `GET /api/v1/clusters/{id}/export?target=&format=csv|html`. CSV: one row per finding (cluster, target, evaluatedAt, severity, category, key, title, detail, teams, namespaces, citations ;-joined). HTML: self-contained (inline CSS, no JS/CDN), header (cluster, target, score badge, KB version, generated-at), findings table grouped by severity, score-history sparkline as inline SVG, citations as links, print-friendly (@media print). Golden tests for both (fixed fixtures).
7. **README**: fleet/gate/export/tokens sections; Action usage snippet.
