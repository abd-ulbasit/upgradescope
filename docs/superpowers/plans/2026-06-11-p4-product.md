**Goal (spec §11 P4):** embedded SPA dashboard; community registry pipeline (contribution docs, validator CI, endoflife.date sync); KB auto-refresh CI; launch polish.

## Track 1 — Dashboard (`web/` + serve embedding)

- Vite + React + TS, **no CDN/runtime deps beyond react/react-dom** (charts hand-rolled SVG — score trend already exists as server-side sparkline concept). Professional dark UI, system font stack, accessible.
- Views: **Fleet** (clusters × targets score matrix from /api/v1/fleet, click-through), **Cluster** (score badge, findings grouped by severity with category/team filters from /report + /findings, trend from /history, teams table from /teams), **Registry** (browse embedded registry via new `GET /api/v1/registry` endpoint — serve from `registry.Load()`).
- Auth: optional read token — settings field stored in localStorage, sent as bearer.
- Build: `web/` with package.json; `make web` → `web/dist` copied to `internal/server/webdist/` (gitignored except `.gitkeep`; embedded via `//go:embed webdist` with a build-tag fallback `nodashboard` that serves 404 — CI builds web first). Serve at `/` (API stays under /api/, /healthz untouched).
- Tests: Go side — static handler serves index.html at /, assets, API routes unaffected, registry endpoint JSON. Web side — `npm run build` green + vitest for the API client module only (no component test theater).
- Update Dockerfile (multi-stage: node build → go build with embed), chart README, main README (screenshot placeholder + `make web` docs).

## Track 2 — Registry pipeline + KB auto-refresh + launch polish

- Schema: optional `endoflife_product: <slug>` field (validator: non-empty when present). New entries (API-synced, citations = endoflife.date product URL + upstream): istio, cilium, calico, argo-cd, flux, keda, kyverno, traefik, etcd, containerd. Hand-curated adds: external-dns, prometheus-operator, velero (compat-matrix citations).
- `tools/eol-sync` (own go.mod, stdlib only): for each registry YAML with `endoflife_product`, GET endoflife.date API, update ONLY `support.status`/`support.eol_date` (latest cycle EOL semantics: product EOL only when ALL non-EOL cycles... keep simple: track the **oldest supported cycle's** EOL? NO — addon-level: status=eol iff the newest cycle is EOL; else supported; record newest-cycle eol_date when boolean false keep empty). Document the rule in the tool. `-check` mode for CI (exit 1 on drift). Makefile `eol-sync`.
- CI: `.github/workflows/kb-refresh.yml` — weekly cron: gen-kb against k8s.io/api@latest (in a throwaway branch of tools/gen-kb go.mod), eol-sync, `peter-evans/create-pull-request` if diff. Registry validator already runs in test job — add a dedicated registry job running `go test ./registry/` + eol-sync -check on PRs touching registry/.
- `registry/CONTRIBUTING.md`: schema reference, citation requirement, how to add an add-on (with template), how matchers work, PR checklist.
- Launch polish: README — measured numbers section (binary size, scan wall-time on the kind demo cluster, image size; MEASURE them, don't invent), architecture diagram (ASCII), "Comparisons" row update (continuous: ✅ shipped), GoReleaser config (.goreleaser.yml: darwin/linux amd64+arm64, no publish — dry-run `goreleaser build --snapshot` if installed, else skip with note).

Exit: `go test ./... -race` green; `make web && go build ./...` green with dashboard embedded; eol-sync runs against live API; dashboard screenshot captured (playwright/browser via agent if available) for README.
